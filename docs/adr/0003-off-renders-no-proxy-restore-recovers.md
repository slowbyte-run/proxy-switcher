# off 渲染无代理状态，restore 才回滚

`off` 的目标是「这个载体现在处于规范的无代理状态」，不是「回到上一次开关之前的字节」。因此 niri 写六个 `null`、shell 写六个显式 `unset`、ssh 写 `ProxyCommand none`，npm/pnpm 删除代理键；如果 `on` 新建了文件或块，`off` 把新建的部分移除，而不是留下一个空壳。

`proxy restore` 是另一件事：按清单里的快照逐字节恢复，原文件本来不存在就删除该文件。它用于显式 undo，也用于把用户原本手写的代理值找回来。

## Why

最初把 `off` 实现成快照恢复，会让「关闭代理」在某些机器上变成「恢复代理」：用户原本可能在 `~/.npmrc` 或 niri 配置里手写过指向旧端口的代理值，回滚快照等于把这些值重新启用。工具的语义必须是可预测的——`off` 之后可以验证环境里没有代理，`restore` 才负责恢复原状。

把两者分开后，快照只剩两个用途：

- 冲突检测：当前哈希 ≠ 上次写入哈希时拒绝覆盖；
- 显式恢复：`proxy restore [载体...]`。

## Consequences

- `off` 与 `restore` 都走临时文件 + rename、保留权限位、遵守冲突检测；`--force` 可以越过冲突。
- 清单里的快照不会被 `off` 消费，重复 `off` 保持幂等。
- `restore` 不改变 `off` 的语义；需要「关掉但保留原值」时，先 `off` 再 `restore` 不是同一个操作，文档和帮助文本必须分开描述。
- 回归测试必须同时覆盖两条路径：`on → off` 得到无代理字节，`on → off → restore` 与初始字节一致。
